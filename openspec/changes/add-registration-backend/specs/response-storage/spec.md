## ADDED Requirements

### Requirement: Persistent storage across restarts
The system SHALL store every accepted submission in a SQLite database file that persists across application restarts and redeployments.

#### Scenario: Submission survives app restart
- **WHEN** the application is restarted after a submission was stored
- **THEN** the previously stored submission is still present in the database afterward

### Requirement: Separate storage per form
The system SHALL store провід and лектор submissions in separate tables, never merged into a shared table.

#### Scenario: Independent tables
- **WHEN** a provid submission and a lecturer submission are both stored
- **THEN** each appears only in its own form's table, not in the other

### Requirement: Complete field capture with server-generated timestamp
Each stored record SHALL include every field collected on its corresponding form plus a timestamp generated by the server at the moment of storage.

#### Scenario: Timestamp recorded
- **WHEN** a submission is stored
- **THEN** the record includes the date and time it was received, generated by the server, not supplied by the client

#### Scenario: All fields present
- **WHEN** a provid submission with name, contact, selected tasks, an idea, and an about-me note is stored
- **THEN** the stored record contains all of those fields, not a subset
